# Dashboard update

The dashboard (`dashboard/index.html`, served at feedback-distillation.exe.xyz)
is the team's shared "active project state" page. It is generated by
`scripts/build_dashboard.py` from **hand-maintained narrative constants** at the
top of that file. This skill keeps them honest. Anyone on the team can run this
skill from their own machine — changes ship as a PR, no access to the host box
needed (a maintainer deploys, or CI does after merge).

## Procedure

1. **Collect what changed since the dashboard's last truth.** Check, in order:
   - `git log --oneline -20 main` and recently merged PRs (`gh pr list --state
     merged --limit 10`) — new results, merged experiment branches.
   - New/updated dirs under `results/` (especially `results/ablation/`,
     `results/diagnostics/`) — read each `processbench_results.json`; respect
     eval-health warnings (a warned cell's F1 is not reportable; ROC-AUC is).
   - `PAPER_FRAMING.md`, `RESEARCH_ROADMAP.md`, `HANDOFF_*.md`, `RUNBOOK_*.md`
     for phase/priority changes.
   - Live deadlines: verify the submission deadline in `PAPER_FRAMING.md` is
     still what the venue says before repeating it.
2. **Edit only the narrative constants** in `scripts/build_dashboard.py`:
   `OVERVIEW` ("Where we are today"), `PHASE`, `RUNS`, `DECISIONS`, `TASKS`,
   `BULLETPROOFING`, `MILESTONES`, `PATH_TO_SUBMISSION`, `FRONTIER`, `LINKS`.
   Rules:
   - Every number must trace to a committed `results/` artifact; put the path in
     the PR body.
   - States are `done | running | queued` (RUNS), `done | now | next | then`
     (milestones/path). Don't invent new states — the CSS won't render them.
   - Follow `PAPER_FRAMING.md` for any wording about claims or framing.
   - Keep entries one-to-two lines; the dashboard is a glance surface, not a lab
     notebook.
3. **Rebuild:** `./.venv/bin/python -m scripts.build_dashboard --out
   dashboard/index.html` (any Python ≥3.10 works; pure stdlib).
4. **Ship as a PR** on a `dashboard/<topic>` branch with the built
   `dashboard/index.html` included. Never push main directly. CI rebuilds on
   merge; a maintainer syncs the VM (or the VM cron pulls, once that lands).

## Editing the frontier/reading-list section

`FRONTIER` entries are `(action, title_with_arxiv_id, one_line_relevance)` where
action ∈ `must-cite | nice | watch`. Add new papers with a one-line reason tied
to OUR claims (not a generic summary). When a paper changes our framing, update
`PAPER_FRAMING.md` in the same PR — the dashboard mirrors doctrine, it doesn't
define it.
